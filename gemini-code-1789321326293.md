# Project: Enterprise Knowledge Assistant (Custom RAG Pipeline)

## 1. Project Overview
We are building a local, single-turn Retrieval-Augmented Generation (RAG) system from scratch. The system ingests enterprise documents (PDFs), splits the text, generates vector embeddings locally, and retrieves the most relevant context using pure mathematical vector search. The retrieved context is then passed to a Large Language Model via API to generate an accurate, source-cited answer.

## 2. System Design & Structure
To maximize learning, we are intentionally avoiding heavy abstraction libraries (like LangChain or ChromaDB) for the core data processing and retrieval pipelines. 
* **Data Parsing:** Standard Python string manipulation and basic PDF libraries (`pypdf`).
* **Chunking:** Custom pure Python sliding window algorithm built from scratch.
* **Embeddings:** Local execution using `sentence-transformers` (`all-MiniLM-L6-v2`).
* **Vector Search:** Pure mathematical execution using `numpy` cosine similarity.
* **Generation:** Direct HTTP API calls to an LLM provider.

## 3. Core Functionalities
* **Multi-Format Ingestion:** Ability to read and extract raw text from `.pdf` files.
* **Custom Text Splitting:** Slices large texts into overlapping blocks to preserve context boundaries.
* **Semantic Vectorization:** Converts raw string chunks into 384-dimensional arrays.
* **Mathematical Similarity Search:** Computes geometric distance between query vectors and document vectors.
* **Fact-Grounded Generation:** LLM generates answers strictly based on retrieved context or replies "Not Found."

## 4. Validation & Debug Output Specification
To verify that custom algorithms are operating as expected before moving to the next phase, each milestone requires explicit output validation:
1. **Week 1 Verification:** Reads a designated test file (`sample.pdf`), computes metrics (character count, total chunks produced), and writes every generated chunk into a formatted text file (`debug_chunks.txt`).
2. **Week 2 Verification:** Converts the chunks into embeddings, runs a fixed benchmark query, computes top-$K$ cosine similarity scores, and writes the top matching chunks along with their exact numerical scores to a text file (`debug_retrieval_results.txt`).

## 5. Development Prompts

### Task: Week 1 - Document Processing & Output Validation Pipeline
**Context:** Build the ingestion pipeline using raw Python without high-level RAG frameworks. Include automated output verification to check chunking behavior.

**Instructions for AI:**
1. Create a Python script named `ingestion.py`.
2. Write a function `extract_text_from_pdf(file_path)` using `pypdf` to extract raw text from a given PDF into a single continuous string.
3. Write a function `custom_text_splitter(text, chunk_size=500, chunk_overlap=50)` strictly from scratch using a standard `while` loop and Python string slicing to generate overlapping string chunks.
4. Add a validation block inside `if __name__ == '__main__':` that:
   - Reads a fixed test file named `sample.pdf` (handling exceptions gracefully if the file is missing).
   - Prints metric updates to the console: Total Raw Characters Extracted, Total Chunks Generated, and Chunk Size / Overlap configuration.
   - Writes all generated chunks to an output file named `debug_chunks.txt` in the following format:
     ```text
     ==================================================
     CHUNK [Index Number] | Length: [Char Length]
     ==================================================
     [Chunk Content String]
     ```

### Task: Week 2 - Vector Storage, Manual Search & Retrieval Validation
**Context:** Implement vector generation and manual cosine similarity search without using vector databases. Add automated validation for search accuracy.

**Instructions for AI:**
1. Create a Python script named `retrieval.py`.
2. Write a function `generate_embeddings(text_chunks)` that uses `sentence-transformers` (`all-MiniLM-L6-v2`) to convert a list of strings into a NumPy array of 384-dimensional vectors.
3. Write a mathematical function `cosine_similarity(vec_a, vec_b)` using `numpy` (computing dot product divided by the product of vector norms).
4. Write a function `search_top_k(query_vector, document_vectors, top_k=3)` that calculates cosine similarity across all document vectors and returns the indices and similarity scores of the top $K$ matches.
5. Add a validation block inside `if __name__ == '__main__':` that:
   - Reads the chunks generated from `debug_chunks.txt` (or runs `ingestion.py` on `sample.pdf`).
   - Converts all chunks into a NumPy embedding matrix and logs embedding execution time and matrix shape `(N, 384)` to the console.
   - Accepts a fixed sample query string (e.g., `"What is the policy guidelines mentioned?"`).
   - Executes `search_top_k` for $K = 3$.
   - Writes the search results to an output file named `debug_retrieval_results.txt` displaying:
     ```text
     QUERY: [Sample Query String]
     --------------------------------------------------
     RANK 1 | SIMILARITY SCORE: [0.XXXX] | CHUNK INDEX: [Index]
     [Matching Chunk Text Content]
     --------------------------------------------------
     RANK 2 | SIMILARITY SCORE: [0.XXXX] | CHUNK INDEX: [Index]
     ...
     ```
